# 260827 강북삼성 예건 HNT-1·HNT-1P 안압계 데이터 통신 규격 요약

> 상위 노트: [[HIE팀 이슈\|HIE팀 이슈]] · [[이슈/강북삼성 인터페이스 내용정리\|강북삼성 인터페이스 내용정리]]

## 검토 목적

강북삼성 예건의 Huvitz `HNT-1`·`HNT-1P` 검사결과 자동화 연동을 검토하기 위해 전달된 PDF 5페이지를 기준으로, 통신 조건·데이터 구조·구현 시 주의사항을 정리한다.

## 결론

- 대상 장비는 Huvitz **HNT-1·HNT-1P 비접촉 안압계**다. `HNT-1P`는 안압(Tono)과 함께 각막두께(Pachy/CCT)를 직접 측정하며, `HNT-1`에는 Pachymeter 측정 기능이 없다.
- 캡처된 결과 전송 규격은 장비가 외부 PC로 검사결과를 보내는 **단방향 RS-232C ASCII 프로토콜**이다. 기본 조건은 **115200 bps, 8 data bits, parity 없음, 1 stop bit(115200 8N1)**이다.
- 검사결과가 존재할 때 장비의 **Print 키를 누르면 인쇄 후 전송**된다. 따라서 현재 문서만으로는 측정 완료 즉시 자동 전송되는 구조가 아니다.
- 메시지는 `CRLF`(`\r\n`)를 사용하며 환자번호, 측정일시, 프로그램 버전, 좌·우 측정값과 평균값을 행 단위로 전송한다. 측정 횟수와 측정한 눈에 따라 행 수가 달라질 수 있다.
- 장비는 상대방 응답을 기다리지 않으며, 문서는 일반적인 `ACK`, `NAK`, `STX` 등을 사용하지 않는다고 설명한다. 표시된 패킷에는 체크섬과 고유 메시지 ID가 없고 재전송 규칙도 기재되지 않아, 수신 프로그램에서 원문 보관·중복 감지·누락 감시가 필요하다.

## 장비 모델별 결과 차이

| 모델 | 장비 성격 | 이 프로토콜에서 예상되는 측정 행 |
|---|---|---|
| `HNT-1` | 비접촉 안압계 | `T-*` Tono(안압) 행. `P-*` 행을 필수로 기대하면 안 됨 |
| `HNT-1P` | 비접촉 안압계 + 내장 Pachymeter | `T-*` Tono(안압) 행과 측정 시 `P-*` Pachy(각막두께) 행 |

휴비츠 제품 규격상 안압 측정 범위는 `0~60 mmHg`이고, HNT-1P의 각막두께 측정 범위는 `150~1300 μm`이다. 다만 **통신 캡처 자체에는 단위와 범위가 포함되지 않으므로**, 수신 DB의 단위는 장비 모델·현장 설정과 대조하여 확정한다.

## 통신 사양

| 항목 | 규격 |
|---|---|
| 인터페이스 | RS-232C serial |
| 전송 방향 | 이 캡처의 결과 프로토콜은 장비 → 외부 PC/장치 단방향 |
| 장비 설정 | User Setup에서 `COM Out` 활성화 |
| 전송 시점 | 측정결과가 있는 상태에서 Print 키 입력 후 인쇄 및 전송 |
| Baud rate | `115200` |
| Data bits | `8 bit` |
| Parity | 없음 (`No`) |
| Stop bit | `1 bit` |
| 문자 형식 | ASCII |
| 행 구분 | `CRLF` (`\r\n`) |
| 응답/제어 | 상대 응답을 기다리지 않으며, 문서는 일반적인 `ACK`·`NAK`·`STX` 등을 사용하지 않는다고 설명 |
| 흐름 제어·핀 배열 | 캡처에 미기재 |

> 휴비츠 제품 브로슈어는 장비의 외부 I/O를 `RS-232C (in/out)`로 표기한다. 이는 장비 전체의 물리 I/O 사양이며, 본 캡처가 설명하는 **검사결과 출력 프로토콜은 단방향**이다. 두 표현을 동일한 의미로 혼동하지 않는다.

> 문서 예시의 `~`는 **공백을 눈에 보이게 표시한 기호**이며 실제 전송 문자인 물결표가 아니다. `\r`은 Carriage Return, `\n`은 Line Feed를 뜻한다.

## 데이터 프레임과 필드

### 전체 구조

개념적인 데이터 흐름은 다음과 같다.

```text
\r\n
NO: <환자번호>\r\n
DATE: <날짜>  <시간>\r\n
VER: <소프트웨어 버전>\r\n
<개별 측정값 행 0~N개>\r\n
<평균값 행>\r\n
\r\n
```

- 시작과 종료에 `CRLF`가 있으며 각 데이터 행도 `CRLF`로 끝난다. 구현 시에는 연속된 빈 행을 한 메시지의 경계로 취급하되, 실제 장비 캡처로 확정하는 것이 안전하다.
- 좌·우 어느 쪽을 몇 번 측정했는지에 따라 개별 측정값 행 수가 달라진다.
- 측정결과가 하나도 없으면 전송하지 않는다.

### 공통 필드

| 필드 | 의미 | 주의사항 |
|---|---|---|
| `NO:` | 환자번호 | **최대 5자리**. 병원 환자번호·처방키와의 매핑 방식 확인 필요 |
| `DATE:` | 측정 날짜와 시간 | 예: `2016/12/14  12:35`. 날짜 형식은 User Setup의 Date 옵션에 따라 달라짐 |
| `VER:` | 장비 소프트웨어 버전 | 예: `1.0.0` |

### 측정값 키 규칙

| 예시 | 구성 | 의미 |
|---|---|---|
| `T-R01: 10` | `T` + `R` + `01` | Tono 측정, 우안, 1번째 측정값 |
| `P-L03: 527` | `P` + `L` + `03` | Pachy 측정, 좌안, 3번째 측정값 |
| `T-R02: 18*` | 값 뒤 `*` | 신뢰할 수 없는 측정값 표시 |
| `T-R-A: 10.0` | `T` + `R` + `A` | 우안 Tono 평균값 |
| `P-L-A: 527.5` | `P` + `L` + `A` | 좌안 Pachy 평균값 |

- 측정 유형: `T` = Tono(안압), `P` = Pachy(각막두께, HNT-1P만 해당).
- 측정 방향: `R` = Right, `L` = Left.
- 측정 순번: `01`~`10`.
- `*`가 붙은 값은 신뢰도 이상 표시이며 장비의 평균 계산에서 제외된다.
- 평균값의 소수점 자릿수는 User Setup의 `Float Average` 옵션에 따라 달라진다.
- 제품 규격상 Tono 값은 `mmHg`, HNT-1P의 Pachy 값은 `μm` 단위이나, 실제 수신 DB 적용 전 실장비 원시 데이터와 함께 확인한다.

> **원문 예시의 오기 의심:** 4페이지 좌안 Pachy 예시는 `P-L03: 527` 다음 행도 `P-L03: 528`로 인쇄되어 있다. 측정 순서와 평균 `527.5`를 보면 두 번째 행은 `P-L04`일 가능성이 높지만, 캡처만으로 임의 확정하지 않는다. 수신기는 중복 키를 즉시 덮어쓰지 말고 원래 순서를 보존하며, 실장비 출력에서 실제 키를 확인해야 한다.

## 자동화 연동 검토

### 구현 가능성

수신 자체는 비교적 단순하다. 지정된 COM 포트를 115200 8N1로 열고 ASCII 바이트를 수신하여 `CRLF` 단위로 행을 분리한 뒤, `:` 앞쪽 키와 뒤쪽 값을 파싱하면 된다. 다만 운영 안정성을 위해 다음 처리가 필요하다.

1. 수신 원문 전체와 수신 시각, 포트 상태를 먼저 로그로 보존한다.
2. 빈 행 또는 연속 `CRLF`를 메시지 경계로 처리하되 실장비 샘플로 시작·종료 조건을 확정한다.
3. `NO`, `DATE`, `VER`는 단일 필드로, `T/P` 측정값은 방향과 순번을 포함한 반복 필드로 처리한다.
4. `*`는 숫자에서 분리하여 `unreliable=true` 같은 별도 상태로 저장한다.
5. 한쪽 눈만 측정하거나 순번이 건너뛰는 경우를 허용하고, 고정 행 수를 가정하지 않는다.
6. 통신 응답과 메시지 고유 ID가 없으므로 동일 원문 해시·수신 시각·환자번호·측정일시를 이용한 중복 감지 정책을 둔다.
7. 환자 자동 매칭 실패 시 다른 환자에게 결과를 넣지 말고 보류 큐 또는 수동 확인 대상으로 전환한다.

### 자동화 전에 확인할 사항

| 우선순위 | 확인 항목 | 이유 |
|---|---|---|
| 필수 | 현장 설치 모델이 `HNT-1`인지 `HNT-1P`인지 | HNT-1에는 Pachymeter가 없어 `P-*` 필드를 필수로 처리하면 안 됨 |
| 필수 | 실제 전송 샘플 3종 이상: 양안, 단안, `*` 포함 결과 | 가변 필드·프레임 경계·공백 수·날짜 형식 검증 |
| 필수 | 좌안 Pachy 4회 이상 측정 샘플의 키 순번 | 문서 예시에 `P-L03` 중복 인쇄가 있어 실제 `P-L04` 출력 여부 확인 필요 |
| 필수 | `NO`에 들어가는 값의 생성·입력 방식과 병원 환자/처방키 매핑 | 최대 5자리만 제공되어 병원 환자번호를 그대로 담지 못할 가능성 |
| 필수 | Print 키 없이 자동 전송할 수 있는 설정 또는 장비 제어 방법 | 문서상 전송 트리거가 수동 Print |
| 필수 | 재출력 시 동일 결과가 재전송되는지 | 메시지 ID와 ACK가 없어 중복 연동 위험 |
| 확인 | 케이블 종류, 커넥터·핀 배열, DTE/DCE, flow control | 캡처에 하드웨어 배선 세부사항이 없음 |
| 확인 | Tono/Pachy 값의 단위와 허용 범위 | 제품 규격은 `mmHg`·`μm`이나 통신 캡처에는 단위 필드가 없음 |
| 확인 | User Setup의 `COM Out`, Date, Float Average 실제 설정 | 전송 여부와 파싱 형식에 직접 영향 |
| 확인 | 전원·케이블 단절 후 재전송/버퍼 동작 | 재처리 및 누락 복구 규칙이 문서에 없음 |

## 권장 현장 검증 절차

1. 현장 장비가 `HNT-1`인지 `HNT-1P`인지 모델명·시리얼번호·소프트웨어 버전과 통신 메뉴 화면을 촬영한다.
2. 터미널 프로그램으로 원시 ASCII 데이터를 저장한다.
3. 양안 정상, 단안, 신뢰도 표시(`*`), 환자번호 경계값, 재출력 케이스를 각각 시험한다.
4. 실제 바이트 기준으로 `CRLF`, 공백, 날짜 형식, 시작·종료 프레임을 확인한다.
5. 환자 매칭 실패·중복 전송·통신 중단 시 운영자 처리 절차를 정한 후 EMR/CIS 자동 반영을 활성화한다.
