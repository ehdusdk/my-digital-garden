## 2. ★ USB 화면이 어긋나는 진짜 원인 — DC 오프셋

12리드 표준 레이아웃은 각 리드를 **자기 2.5초 구간만** 그립니다.

```
0~2.5s : I, II, III        2.5~5s : aVR, aVL, aVF
5~7.5s : V1, V2, V3        7.5~10s: V4, V5, V6      (맨 아래 리듬스트립 II는 0~10s 전체)
```

각 리드를 **자기 표시 구간**에서 기저선(중앙값)을 재면:

| 리드 | 표시 구간 | NET µV | NET mm | **USB µV** | **USB mm** |
|---|---|---|---|---|---|
| I | 0~2.5s | −115 | −1.1 | −224 | −2.2 |
| II | 0~2.5s | 45 | 0.5 | 67 | 0.7 |
| III | 0~2.5s | 160 | 1.6 | 298 | 3.0 |
| aVR | 2.5~5s | −10 | −0.1 | −1 | −0.0 |
| aVL | 2.5~5s | −35 | −0.3 | −221 | −2.2 |
| aVF | 2.5~5s | 50 | 0.5 | 242 | 2.4 |
| **V1** | 5~7.5s | −20 | −0.2 | **−1,999** | **−20.0** |
| **V2** | 5~7.5s | 325 | 3.2 | **+3,020** | **+30.2** |
| V3 | 5~7.5s | 55 | 0.6 | −21 | −0.2 |
| **V4** | 7.5~10s | −80 | −0.8 | **−1,706** | **−17.1** |
| **V5** | 7.5~10s | 165 | 1.6 | **−1,092** | **−10.9** |
| **V6** | 7.5~10s | 75 | 0.8 | **−3,778** | **−37.8** |

(mm 은 10 mm/mV 인쇄 게인 기준)

### 해석

- **Network는 전 리드가 ±3.2 mm 이내** → 각 행 안에 정상 배치
- **USB는 흉부유도 5개가 11~38 mm 벗어남** → 한 행 높이를 훌쩍 넘어 옆 행을 침범하거나 잘려 나감
- **V3만 −0.2 mm로 정상** → 첨부 이미지에서 V3만 멀쩡해 보이는 것과 정확히 일치합니다
- V2가 +30 mm 위로, V4~V6가 −11~−38 mm 아래로 → 이미지의 "뒤쪽 어긋남" 현상 그대로

### 왜 USB에만 생기나

| | hipass | 시정수 τ = 1/(2πf) | 10초 기록에서 DC 제거 |
|---|---|---|---|
| Network | 0.05 Hz | 약 3.2초 | 상당히 제거됨 |
| **USB** | **0.02 Hz** | **약 8초** | **거의 안 빠짐** |

USB는 장비 내부 아카이브 원본이라 0.02 Hz 광대역입니다. 10초 기록의 DC 성분이 그대로 살아 있고, 파서가 원본을 충실히 전달하므로 **DC가 화면까지 그대로 옵니다.**

**장비 사양상 예상되는 현상이며, 수신 측에서 처리해야 하는 부분입니다.**

## 4. 권장 조치

### A안 — `m_nBaselineOffset` 채우기 ★ 권장

렌더러는 이미 리드별 기저선 오프셋 필드를 지원합니다.

```cpp
// CISREOBJ_EcgPage.cpp 619행
pPTs[nPTPos].Y = rStartY + ((rBaseline - (REAL)sMinVal) * rRatioY);
//                           ^^^^^^^^^ = pREWave->m_nBaselineOffset, 원시 샘플과 같은 LSB 단위
```

즉 **`m_nBaselineOffset` 에 리드별 중앙값(LSB)을 넣으면 샘플 데이터를 하나도 건드리지 않고 화면만 중앙 정렬**됩니다. 출력 XML의 `<BaselineOffset>` 에도 기록되어 하류 뷰어도 활용할 수 있습니다.

`ConvertWave()` 의 리드 복사 루프 직후(페이싱 보정 블록 근처)에 추가:

```cpp
// [Add] 표시용 기저선 오프셋 기록 — 샘플 데이터는 원본 그대로 유지
//   USB(hipass 0.02Hz) 원본은 DC 성분이 거의 남아 있어 그대로 그리면 리드가 화면을 벗어난다.
//   렌더러가 Y = (m_nBaselineOffset - sample) * ratio 로 쓰므로 중앙값을 넣으면 중앙 정렬된다.
for(i = 0; i < nLeadCnt; i++)
{
    pREWave = ECGOut.m_WaveInfo.GetWave(aLead[i]);
    if(pREWave == NULL) continue;
    PSHORT p = pREWave->GetWaveBuffer();
    int n = pREWave->GetSampleCount();
    if(p == NULL || n <= 0) continue;

    // 중앙값(정렬 비용이 부담되면 평균으로 대체 가능)
    CArray<short,short> ar;  ar.SetSize(n);
    for(int k = 0; k < n; k++) ar[k] = p[k];
    // ... 정렬 후 ar[n/2] 를 취함 ...
    pREWave->m_nBaselineOffset = (int)median;
}
```

> 중앙값이 평균보다 안전합니다. QRS 같은 큰 편위에 덜 끌립니다.
> **Network 영향**: 기저선이 이미 ±3 mm 이내라 오프셋이 거의 0 → 사실상 변화 없음. 회귀 위험 낮음.
