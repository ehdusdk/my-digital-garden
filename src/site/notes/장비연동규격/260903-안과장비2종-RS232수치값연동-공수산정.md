## 1. 수치값 처리 경로 (소스 분석 결과)

| 단계 | 모듈 | 하는 일 | 산출물 |
|---|---|---|---|
| 1 | **CISModalityLib** | `CISRS232Receiver`(프레임워크 기존재) + 장비별 `CISNumericParser` 서브클래스가 패킷 파싱 | ND XML, `Measurement@designID` |
| 2 | **CISReceiver** | 자동매칭, `CISMatchingThread::InsertNumericData()`로 CIS DB 저장, `CISParser::UseCDWUploader(TRUE)` | NUM_CDW XML (CDWGUID 폴더) |
| 3 | **CISNEIS / CISNEISLite** | 오더-검사 매칭 확정 시 매칭정보 XML 기록 (`OnBnClickedMatch`) | `MatchedInfo_YYYYMMDDHHMMSS.xml` |
| 4 | **LocalCDWExporter** | matchedinfo 폴링 → CDWGUID로 수치 XML 페어링 → `Local\Designdata\<designID>.xsl` XSLT 변환 | `exportdatainfo.xml` (`<item name value>`) |
| 5 | **CDW 전송 API** | 토큰 발급 후 POST | `cisLnkgNo`, `cisWodvCd:"N"`, `cisPrssCd:"N"`, `ptno`, `crtnDt`, `cisExmnRsltList[{exmnCd, rsltCtn}]` |

### 1-1. 핵심 결론

> **신규 장비의 코드 작업은 대부분 `CISModalityLib`에 집중된다.**
> LocalCDWExporter는 원칙적으로 **코드 변경 없이** `<designID>.xsl` 1개 + 검사코드 매핑 추가로 대응된다. (단, 2절의 제약 2건은 예외)

### 1-2. RS232 수신 위치 정정

`CIS_1400\trunk\Source\CISReceiver`에는 시리얼 통신 코드가 **없다**. RS232 수신은 `D:\Proj\CIS_LIB_2008\CISModalityLib`의 `CISRS232Receiver` / `CISRS232ReceiverSetting`이 담당하며, CISReceiver는 그 결과물인 ND XML을 받아 매칭·DB 저장·CDW 업로드용 XML 생성을 수행한다.

참고 구현 (Topcon KR-800A, 26/02~03 작업):

```cpp
// Topcon_KR_800A.cpp
m_uAvailableReceivers = cis_interface_type_Polling | cis_interface_type_RS232;
SetParserRTC(RUNTIME_CLASS(Topcon_KR_800A_Parser), RUNTIME_CLASS(CISNumericParserSetting));

case cis_interface_type_RS232:
{
    CISRS232ReceiverSetting RcvSet;
    pReceiver = CISModality::OnCISModality_CreateReceiver(RcvType);
    pReceiver->GetReceiverSetting(&RcvSet);
    RcvSet.SetRS232Port(1);
    RcvSet.SetRS232(_BAUD_RATE, _DATA_BITS, _STOP_BITS, _PARITY);
    pReceiver->SetReceiverSetting(&RcvSet);
}
```

## 2. LocalCDWExporter 확인 필요 사항

> 중간 처리 과정이 미확인 상태였던 구간. 소스 확인 결과 이번 연동에 직접 영향을 주는 제약 2건이 있다.

### ① 수치 XML을 1건만 변환한다

`LocalCDWExportRoutine::TransformProcessingDataToExportInfo()`

```cpp
// 간단하게 첫 번째 파일만 변환하는 예 (필요시 병합 로직 추가)
strNumericPath = movedFiles[0];
```

VAA처럼 **시력 패킷과 색각/녹내장 패킷이 서로 다른 XML로 떨어지면 한 건만 CDW로 전송**된다.
→ 병합 로직 보완 필요 (**3인일, 공통 기반에 포함**)

### ② CDWGUID를 1개만 읽는다

`ParseMatchedInfo()`는 `WRXml::GetChildNodeText2(pMatchedInfoNode, _T("CDWGUID"))`로 **첫 노드만** 읽는다. 반면 CISNEISLite는 선택한 검사 수만큼 `CDWGUID` 노드를 기록한다.
→ 한 오더에 검사 2건 이상 매칭하는 운영이면 동일한 누락 발생

### ③ XML 형식 보정 이력

`RepairMalformedCdwGuidCloseTag()` 보정 루틴이 이미 들어가 있다 (닫는 태그가 `<CDWGUID>`로 중복 기록된 케이스 대응). 매칭정보 XML 생성 측 오작성 이력이 있었던 것으로 보이므로, 신규 항목 추가 시 **XML 형식 검증을 테스트 항목에 포함**한다.

### 참고: API 전송 본문 구성 (`FillCDWExportData`)

```cpp
body["cisLnkgNo"] = strAccNo;   // cis연동번호 (ACCN)
body["cisWodvCd"] = "N";        // CIS작업구분코드 (N 고정)
body["cisPrssCd"] = "N";        // CIS진행상태코드 (N: 수치, T: 판독)
body["ptno"]      = strPatID;   // 환자ID
body["crtnDt"]    = strCrtnDt;  // 생성일시
// item 반복: exmnCd = <item name>, rsltCtn = <item value>
body["cisExmnRsltList"] = items;
```

## 4. Huvitz HNT-1 / HNT-1P — 15인일 (0.75 M/M)

### 4-1. 난이도가 낮은 이유

- **같은 벤더의 선례가 이미 있다**: `Source/HuvitzModality/Huvitz_HNT_7000.cpp` (251줄) + `CISModalityDesign/Huvitz_HNT_7000_Page.cpp` (173줄)
- **전송 포맷이 동일 계열**: `NO:` / `DATE:` 헤더, `R-01…R-A` / `L-01…L-A` 측정행, 신뢰도 이상 `*` 표기, **115200 8N1 단방향**
- HNT-1P는 여기에 `T-`(Tono) / `P-`(Pachy) 프리픽스와 `VER:` 행 처리만 추가
- **값 코드 신규 정의 불필요** — 아래가 모두 마스터에 이미 있다

| 항목 | 코드 |
|---|---|
| 안압 개별/평균 | `VCode_IOP_R_NOR` / `VCode_IOP_R_AVG` / `VCode_IOP_L_NOR` / `VCode_IOP_L_AVG` |
| 안압 신뢰도 이상(`*`) | `VCode_IOP_R_APX` / `VCode_IOP_R_APX_AVG` / `VCode_IOP_L_APX` / `VCode_IOP_L_APX_AVG` |
| 각막두께 | `VCode_CCT_R_NOR` / `VCode_CCT_R_AVG` / `VCode_CCT_L_NOR` / `VCode_CCT_L_AVG` |
| 단위 | `UCode_mmHg`, `UCode_um` |

> HNT-7000 파서는 이미 `*` 표기를 읽어 `_APX` 코드로 분기하고 있다. HNT-1P의 "신뢰도 이상 값은 평균 계산에서 제외" 규칙과 정합성 확인만 하면 된다.

## 5. ViewM VAA-2000PCE — 32인일 (1.60 M/M)

### 5-1. 난이도가 높은 이유

1. **신규 벤더** — `cis_modality_vendor_*` enum에 뷰엠테크놀로지가 없다. Modality DLL 프로젝트를 새로 만들어야 한다.
2. **신규 값 코드** — 시력·색각 계열 코드가 `ValueMasterDefine.h`에 전무하다. (안과 장비는 굴절·안압·각막두께 위주로만 정의되어 있음)
3. **환자 식별 불가** — 패킷에 **환자ID·측정일시가 전혀 없다**. `m_NDFile.m_PatInfo.m_ID`가 비어 CISReceiver 자동매칭 룰이 성립하지 않는다.
4. **판정 코드가 수치가 아니다** — 색각/녹내장/백내장은 double 값이 아니라 코드값. `CISNumericItem::m_Original`(문자열) 활용 + CDW `rsltCtn` 표현 협의 필요.
5. **패킷 2종** — 시력 25자 `<ESR18…>` / 색각·안질환 8자 `<CBR01x>`. 하나의 measurement로 합칠지 별도 검사로 나눌지 설계 결정 필요 (2절 ①과 직결).

### 5-3. 파싱 시 반드시 지킬 것 (규격서 노트에서 이월)

- 시력값은 **좌 → 우**, 상태값은 **우 → 좌 → 양** 순서 — 순서가 다르다
- **상태값은 2024.10.22 개정 이후 미사용** → 판정 로직에 절대 사용 금지
- 측정거리는 **4바이트 고정, 뒤 공백 포함**(`"5m  "`) → trim 주의
- Single / Quick mode에서 양안 3바이트는 **공백**, 상태는 `X`
- 체크섬·메시지 ID·ACK 없음 → **중복 수신 감지 정책** 필요
