# 오라클 데이터베이스 26ai (Oracle Database 26ai) 도입 및 호환성 분석 보고서

## 1. 버전 개요 및 온프레미스 지원 여부

**Oracle AI Database 26ai**는 오라클의 최신 장기 지원(LTS) 데이터베이스 버전입니다. 기존 23ai의 릴리스 업데이트 형태로 연장 선상에 있으며, AI 관련 기능(AI Vector Search 등)이 코어 엔진에 내장되어 있는 것이 가장 큰 특징입니다.

> [!NOTE]
> **온프레미스(On-Premise) 지원**
> 최근 버전들이 오라클 클라우드(OCI)에 먼저 출시(Cloud-First)되기 때문에 "클라우드 전용"이라는 오해가 있으나, **오라클 26ai는 온프레미스 환경(자체 서버, Exadata, Linux x86-64 등)을 완벽하게 지원**합니다. 기업의 인프라 전략에 맞춰 유연한 배포가 가능합니다.

## 2. 이전 버전 호환성 매트릭스

26ai로의 전환 시 고려해야 할 이전 버전과의 주요 호환성은 다음과 같습니다.

| 호환성 구분 | 대상 이전 버전 | 호환 및 지원 여부 | 상세 내용 및 주의사항 |
| :--- | :--- | :--- | :--- |
| **DB 직결 업그레이드** | **Oracle 23ai** | 🟢 완벽 호환 (RU 패치) | 메이저 업그레이드 없이 릴리스 업데이트(RU 23.26.0 이상) 적용으로 전환. |
| | **Oracle 19c, 21c** | 🟢 직접 업그레이드 지원 | `AutoUpgrade` 툴을 활용한 다이렉트 마이그레이션 권장. |
| | **Oracle 18c, 12c, 11g ↓** | 🔴 직접 업그레이드 불가 | 19c 등 중간 버전으로 선행 업그레이드 후 26ai로 진입하는 2단계 과정 필수. |
| **클라이언트 연결** | **Oracle Client 19c, 21c, 23ai** | 🟢 연결 지원 (64-bit) | 해당 버전들의 64비트 클라이언트는 26ai 서버와 공식적으로 연동 가능. |
| | **32-bit 클라이언트 (전체)** | 🔴 26ai용 배포 중단 | 26ai부터는 32비트용 오라클 클라이언트 설치 파일이 제공되지 않음. |
| **아키텍처 강제** | **Non-CDB (단일 DB)** | ⚠️ 호환 불가 (PDB 변환) | 기존 Non-CDB 구조는 지원하지 않음. 업그레이드 시 PDB로 영구 전환됨. |

## 3. 레거시 32-bit 클라이언트 (VC2008 C++) 환경 연결 분석

현재 운영 중인 시스템이 **Visual Studio 2008 (VC2008) 기반의 32-bit C++ 애플리케이션**이며, 기존의 32-bit 오라클 클라이언트를 통해 26ai 서버와 통신해야 하는 경우에 대한 기술적 분석입니다.

### 3.1 연결 가능 여부 (Technical Connectivity)
> [!TIP]
> **기본적인 통신(SELECT, DML)은 가능합니다.**

26ai에서 "32-bit 지원을 중단"했다는 것은 새로운 26ai용 32-bit 클라이언트 소프트웨어를 배포하지 않는다는 의미입니다. 오라클의 네트워크 통신 프로토콜(SQL*Net) 자체는 클라이언트의 아키텍처(32bit/64bit)를 구분하지 않습니다.
따라서, **기존 클라이언트 PC에 설치된 19c 이하의 32-bit 오라클 클라이언트(OCI)를 그대로 유지**한다면, 네트워크를 통해 64-bit 26ai 서버에 정상적으로 접속하고 쿼리를 수행할 수 있습니다. (32-bit VC2008 애플리케이션은 아키텍처 한계상 64-bit oci.dll을 로드할 수 없으므로 반드시 기존 32-bit 클라이언트를 유지해야 합니다.)

### 3.2 잠재적 리스크 및 주의사항 (Risk Assessment)
당장 연결이 끊어지는 'Hard break'는 발생하지 않지만, 다음과 같은 장기적 제약이 따릅니다.

1. **공식 기술 지원(Technical Support) 제약:** 
   오라클 공식 매트릭스 상 최신 DB와 구형 32-bit 클라이언트의 조합은 권장되지 않습니다. 메모리 누수, 크래시 등 복잡한 문제가 발생했을 때, 오라클 측에 장애 대응(SR)을 요청하면 "지원되는 최신 64-bit 클라이언트로 업그레이드 후 재현하라"는 요구를 받을 수 있습니다.
2. **신규 기능 접근 한계:**
   26ai에 새롭게 도입된 데이터 타입, 고도화된 AI 함수, 혹은 향상된 네트워크 암호화 옵션 등을 C++ 클라이언트 단(OCI 레벨)에서 직접 활용하기 위해서는 클라이언트 라이브러리 지원이 필수적이나, 구형 32-bit 라이브러리에서는 이를 인식하거나 처리하지 못할 수 있습니다.
3. **보안 프로토콜 비호환 가능성:**
   VC2008은 지원이 종료된 구형 런타임을 사용합니다. 향후 DB 서버 설정에서 강력한 최신 TLS 프로토콜 통신만을 강제하도록 설정될 경우, 클라이언트의 OS 및 런타임 제약으로 인해 Handshake 단계에서 연결이 거부될 위험이 있습니다.

### 3.3 최종 권장 전략 (Recommendation)
단기적으로는 현재의 32-bit 클라이언트를 활용하여 26ai 서버로 연결을 유지하더라도 서비스 중단은 피할 수 있습니다. 하지만 장기적인 안정성과 오라클의 완벽한 기술 지원을 확보하기 위해, 애플리케이션 소스 코드를 최신 개발 환경(Visual Studio 최신 버전)으로 마이그레이션하고 **64-bit (x64) 아키텍처로 재컴파일하여 64-bit 26ai 클라이언트와 연동하는 것을 차기 핵심 과제로 수립**하시는 것을 강력히 권장합니다.
