# 1. CISOutBroker 상세

## 1-1. 🆕 `CISBrokerJobPatcherForKUMC.h`

**참조 원본**: `CISDualBroker\trunk\Source\CISDualBroker\CMC\CISOutbroker\CISBrokerJobPatcherForCMC.h`

```cpp
#pragma once

//---------------------------------------------------------------
// 고대병원 Outbroker Patcher
//  - CIS 작업 큐에서 배정받은 작업을 EHR REST API로 전송한다.
//  - 기존 Worker::SetExamResult() 를 그대로 이식한 것이 본체.
//---------------------------------------------------------------
class CISBrokerJobPatcherForKUMC : public CISOutBrokerJobPatcher
{
public:
    CISBrokerJobPatcherForKUMC();
    ~CISBrokerJobPatcherForKUMC(void);

    // CISBrokerFactory::CreatebrokerObject() 에서 최초 1회 호출.
    // FALSE 반환 시 Factory 전체가 기동 실패하므로 주의.
    virtual BOOL InitInstance();

    // CISOutBrokerJobWorker::RunInstance() 에서 작업 1건마다 호출.
    virtual BOOL OnOutbrokerRutine(CISOutbroker_JOB* pJob, CString& strResultComment);

    void SetConfig(const ConfigManager::CONFIG& cfg) { m_Config = cfg; }

protected:
    //--- 기존 Worker.cpp 에서 그대로 이식 ---
    CString GetWorkCode (LPCTSTR lpszCisActionCode, CISOutbroker_JOB* pJob); // Worker.cpp  90행
    CString GetEquipCode(CISOutbroker_JOB* pJob);                            // Worker.cpp 139행
    CString GetReportText(CISOutbroker_JOB* pJob);                           // Worker.cpp 195행

    //--- CISOutBrokerHelper 에서 이식 (설계서 D-2 ①안) ---
    BOOL GetReport(long nOrderKey, CArray<CISBrokerData_Report*>& arReport);  // Helper.cpp 595행
    void SetBasicParam(CISDBParameter& dbParam);                             // Helper.cpp 에서 이식
    void ClearReport(CArray<CISBrokerData_Report*>& arReport);

    CISDatabase           m_CISDB;   // 판독문 조회 전용 커넥션
    ConfigManager::CONFIG m_Config;
};
```

**설계 포인트 3가지**

1. `m_Reports` 문제 — 라이브러리의 `CISOutbroker_JOB`(`CISBrokerData.h` 98~112행)에는 `m_Reports` 가 없습니다. 그래서 Patcher가 **자체 `CISDatabase` 로 판독문을 직접 조회**하고 지역 배열로 다룹니다. 라이브러리 무수정 원칙을 지키기 위한 선택입니다.
2. `m_nOutboundKey` → `m_nInferfaceKey` — 라이브러리 타입의 필드명입니다. 값의 의미는 동일(`t_OutboundDataGroup.ODG_Key`).
3. `InitInstance()` 는 REST 연동이라 EMR DB 접속이 없지만, **판독문 조회용 CIS DB 접속은 여기서** 해야 합니다.

### (b) `OnOutbrokerRutine()` — 핵심

기존 `Worker.cpp` 147~193행 `SetExamResult()` 의 **본문을 거의 그대로** 옮깁니다. 변경점은 ①판독문 선조회 ②`strResultComment` 채우기 ③필드명 2개뿐입니다.

```cpp
BOOL CISBrokerJobPatcherForKUMC::OnOutbrokerRutine(CISOutbroker_JOB* pJob, CString& strResultComment)
{
    // ── [추가] 판독문 선조회 (라이브러리 Worker는 Report를 수집하지 않음) ──
    CArray<CISBrokerData_Report*> arReport;

    if(!GetReport(pJob->m_Order.m_nOrderNo, arReport))   // ※ OrderKey 출처는 1-2(c) 참고
    {
        strResultComment = _T("FAIL:Can't get report");
        ClearReport(arReport);
        return FALSE;
    }

    // ── 이하 기존 Worker::SetExamResult() 와 동일 ──
    SetLog_MajorInfo(cis_log_category_APP, CISGF::FormatString(
        _T("JOB ->InterfaceKey:%d ACCNO:%s PID:%s"),
        pJob->m_nInferfaceKey,          // [변경] m_nOutboundKey → m_nInferfaceKey
        pJob->m_Order.m_strAccNo,
        pJob->m_Order.m_strPatid));

    SKHttpMessage Message;
    SKHttpClient  Client;
    SKCondition   Cond;
    Message.SetHeader(_T("Accept:application/json"));
    Message.SetHeader(_T("Content-type:application/json; charset=utf-8"));
    Message.SetHeader(CISGF::FormatString(_T("x-ncp-apigw-api-key:%s"), m_Config.m_EMR.strWebAPIKey));

    Json::Value        Value;
    Json::StyledWriter Writer;
    std::string        strJson;

    Value["cisLnkgNo"]  = (char*)CT2A(pJob->m_Order.m_strAccNo, CP_UTF8);
    Value["ptno"]       = (char*)CT2A(pJob->m_Order.m_strPatid, CP_UTF8);
    Value["cisWodvCd"]  = (char*)CT2A(GetWorkCode(pJob->m_strActionType, arReport), CP_UTF8);
    Value["emprId"]     = (char*)CT2A(pJob->m_Order.m_strLoginId, CP_UTF8);
    Value["eqpmCd"]     = (char*)CT2A(GetEquipCode(pJob), CP_UTF8);
    Value["exrsCtn"]    = (char*)CT2A(GetReportText(arReport), CP_UTF8);
    Value["rsltTrasDt"] = (char*)CT2A(COleDateTime::GetCurrentTime().Format(_T("%Y%m%d%H%M%S")), CP_UTF8);
    strJson = Writer.write(Value);

    Message.SetBody((LPBYTE)strJson.c_str(), strJson.length());

    CString strURL;
    strURL.Format(_T("%s/szi/cis/infinitt/exmn/rslt"), m_Config.m_EMR.strWebServiceURL);
    Cond = Client.Post(strURL, Message);

    ClearReport(arReport);

    if(Cond.IsGood())
    {
        strResultComment = _T("SUCCESS");
        SetLog_MajorInfo(cis_log_category_APP, _T("JOB -> SUCCESS"));
        return TRUE;
    }

    // ── [추가] 실패 사유를 BWJ_RESULT(VARCHAR2 255)에 남긴다 ──
    strResultComment = CISGF::FormatString(_T("FAIL:HTTP %d %s"),
                                           Message.GetResponseCode(), Cond.GetMessage());
    if(strResultComment.GetLength() > 250)
        strResultComment = strResultComment.Left(250);   // ★ 컬럼 길이 초과 방지 필수

    CISLog_Error(cis_log_category_APP, 0, Cond.GetMessage(), _T(""));
    return FALSE;
}
```

## 2-3. ⚠ EMR Key 보관 위치 — 설계 결정 필요

고대 EHR API는 처리 완료 통보 시 `cisSno`(처방) / `rltnInfmKeyVl`(사용자) 를 되돌려줘야 합니다. 그런데 `CISBrokerParam_Order` / `_User` 에는 EMR PK 전용 필드가 없습니다.

| 안 | 방법 | 평가 |
| --- | --- | --- |
| **① `m_Etc1` 전용 (권장)** | `CISBrokerParam_Order::m_Etc1`(110행), `CISBrokerParam_Patient::m_Etc1`(62행) 를 EMR Key 보관용으로 전용 | **✅ 안전 확인됨** — 라이브러리 전체를 검색한 결과 `m_Etc1` 은 **선언만 되어 있고 어디서도 읽지 않습니다.** 자유롭게 전용 가능 |
| ② `m_Comment` 사용 | `Inbroker_AddJob` 의 `pvComment` (`CISBrokerJobCommander.cpp` 1227행) → `T_INBROKERWORKERJOB.BWJ_Comment` 로 DB 저장 | 값이 큐 테이블에 남아 추적·지연통보에 유리. **단 파라미터 길이가 100자로 제한**(`AddParam_String(…,100,…)`)되고 컬럼도 `VARCHAR2(100)` |

## 3-1. 🆕 `Config\OutBroker\ModuleConfig.ini`

프로그램이 자동 생성하므로 배포 시 **빈 파일이거나 없어야** 합니다.

```ini
[OutBroker]
Name=
Path=
IP=
```

**⚠ 섹션명 주의** — `CISBrokerFactory::RegisterBroker()` 124~131행이 하드코딩합니다.

```cpp
case broker_type_Inbroker:  strConfigSection = _T("InBroker");   // 파일: Config\InBroker\ModuleConfig.ini
case broker_type_Outbroker: strConfigSection = _T("OutBroker");  // 파일: Config\OutBroker\ModuleConfig.ini
```

서울성모 실제 파일에는 `[Broker]` 와 `[InBroker]` 두 섹션이 공존하는데, **읽는 것은 `[InBroker]`** 입니다. `[Broker]` 는 구버전 잔재이니 고대에는 만들지 마십시오.

**⚠ 2호기 배포 시 최대 함정** — 1호기 폴더를 복사하면 `Name`(GUID)이 같아져 **두 노드가 하나의 브로커로 인식**됩니다. 2호기에서는 반드시 `Name=` 을 비우고 기동하십시오.
